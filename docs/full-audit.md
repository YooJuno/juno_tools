# 전체 흐름 재검토

2026-10-29. 비교 기준은 `233a5e7`(버전 4)이며, 수정본은 버전 5입니다. 대상은 기존 GitHub 배포와 로컬 설치, GNOME 46의 실행 흐름입니다.

## 재현하고 수정한 문제

| 문제 | 재현 결과 | 수정 |
| --- | --- | --- |
| 종료 후 파일 캐시가 다시 만들어짐 | 중지한 수집기에 늦게 도착한 읽기를 호출하면 파일 객체가 다시 1개 저장됨 | 중지 뒤 파일 객체 생성·후속 탐색을 차단하고 캐시 정리 |
| 시간 초과 뒤 오래된 결과가 기준값으로 저장됨 | CPU 읽기를 지연시키면 시간 초과 후 도착한 값이 다음 델타의 기준값이 됨 | CPU·온도 세대 무효화, 디스크 상태 분리로 늦은 값의 재사용 방지 |
| 선택한 GPU가 조용히 바뀜 | NVIDIA 조회 실패 후 같은 인덱스에서 AMD 사용률이 반환됨 | 장치 슬롯과 식별자를 유지하고, 사라진 장치는 `—`로 표시 |
| 드라이버의 GPU 번호 재배정 | 물리 장치가 같은 번호를 재사용하면 선택 대상이 바뀔 수 있었음 | NVIDIA UUID와 AMD PCI 주소를 사용해 실행 중 선택을 유지 |
| 모든 표시를 꺼도 CPU 수집 계속 | CPU 표시를 강제로 남기는 동작이 있었음 | 설정 아이콘만 남기고 주기 타이머·백그라운드 수집 중지, 재개 때 델타 기준값 초기화 |
| GPU 끄기가 다른 수집을 기다림 | 수집 중 설정 변경은 후속 갱신까지 대기 | GPU 표시를 끄는 순간 프로세스 중지 요청 |
| 설정창의 동기 파일시스템 조회 | 경로 적용에서 `query_exists()`를 UI 스레드에서 실행 | 비동기 검증, 1.5초 제한, 작업 중복 방지, 창 닫기·입력 변경 후 결과 폐기 |
| 설치·활성화 정책 무시 | 설치 금지나 읽기 전용 설정을 확인하지 않고 복사·성공 안내 가능 | 설치 정책 확인, 모든 변경의 쓰기 권한 선확인, 지연 적용·실패 복구·저장 값 확인 |
| 설치 교체 실패에 취약 | 기존 디렉터리에 파일을 차례로 덮어씀 | 같은 파일시스템에서 새 설치를 검증한 뒤 교체, 실패하면 이전 디렉터리 복구 |
| CI의 오래된 실행 환경·변경 가능한 태그 | Node 20 기반 액션의 런타임 강제 전환 경고 | 확인한 공식 액션 버전을 전체 커밋 SHA로 고정, Node 24, 최소 권한과 작업 제한 시간 유지 |

AMD 센서의 범위를 벗어난 사용률과 음수 VRAM 값도 `—`로 처리합니다. GPU UUID는 장치 식별을 위해 로컬 메모리에서만 사용하며, 기본 센서 검사 출력에서는 제외합니다.

## 프로세스와 실행 정책

기존 NVIDIA 반복 조회의 프로세스 재사용은 유지합니다. 파이프 읽기, 버퍼·장치 수 제한, 무응답 감지, 30초 재시도 지연, 미수거 자식 최대 4개 제한을 재검사했습니다. GPU 끄기·확장 종료·주기 변경의 정리 경로도 검사했습니다. 이 PC의 NVIDIA 도구는 부모 종료로 표준 출력 파이프가 닫힌 뒤 종료되는 것을 별도 프로세스로 확인했습니다.

설치 시 `--enable`을 명시한 경우에만 활성화 목록과 전역 사용자 확장 설정을 변경합니다. 변경이 필요한 키 중 하나라도 정책으로 잠겨 있으면 쓰기 전에 실패합니다. 이미 원하는 상태인 잠긴 키는 다시 쓰지 않습니다. `allow-extension-installation=false`이면 설치 파일 교체도 시작하지 않습니다.

확장 생명주기와 프로세스 정리 기준은 [GNOME 검토 지침](https://gjs.guide/extensions/review-guidelines/review-guidelines.html)을 참고했습니다. 설치 차단 키와 활성화 잠금 검사는 설치된 GNOME 46의 동작을 따릅니다. 런타임은 권한 상승이나 드라이버 설정 변경 없이 센서를 읽으며, 네트워크 전송·원격 코드 설치·텔레메트리를 추가하지 않았습니다. `activation.js`는 설치 보조용으로 ZIP에 포함하지 않습니다. 시스템 `.deb` 활성화는 사용자 설치 금지 키와 구분하되 활성화 설정의 쓰기 잠금은 그대로 존중합니다.

## 검증

- Node 검사 22개: 파서, 갱신 병합·경합, 상세 메뉴 지연 수집, 전체 끄기, 비동기 경로 검증.
- GJS 센서 검사: 실제 RTX 4060/NVMe 수집, 느린 작업·늦은 결과·종료 처리, 장치 슬롯·재연결·잘못된 센서 값.
- GJS 프로세스 검사: 스트림 분할, 여러 GPU, 진단 메시지, 프로세스 재사용·교체·종료, 무응답·재시도·출력 제한.
- 활성화 검사: 설치 금지, 읽기 전용 키, 선검사, 반복 실행, 지연 쓰기 실패 복구와 저장 값 검증.
- 설치 검사: 기존 파일 보존, 첫 로그인 전 활성화 저장, 교체 실패를 주입한 뒤 원래 디렉터리와 파일 복구.
- 별도 GNOME 세션: 밝은/어두운 테마, 실제 메뉴, 전체 끄기·재개, GPU 프로세스 종료, 확장 재시작, GTK 설정창의 비동기 경로 적용.
- 배포 패키지: `.deb` 파일 소유권·권한, GLib 시스템 스키마 트리거, 사용자 활성화, 기존 설치 백업 전환, APT 의존성 모의 설치. `.deb`에서 추출한 런타임과 시스템 스키마를 별도 GNOME 세션에서 함께 실행했습니다.

기존 성능 측정은 [성능·안정성 검토](performance.md)에 보존했습니다. 같은 PC에서 각 반복 뒤 2초 대기하며 6회를 추가 비교했습니다. 버전 4의 평균/중앙값은 2.18/2.26ms, 버전 5는 2.45/2.22ms였고, 전체 검사 CPU 시간은 0.10/0.09초였습니다. 표본이 작아 추가 속도 향상으로 해석하지 않습니다. 이번 변경은 기존의 약 2ms 수준을 유지하면서 경계 상황과 실행 정책을 보완합니다.

네트워크 파일시스템이나 드라이버의 커널 I/O가 멈춘 경우 제한 시간은 UI 대기를 끝내는 시간입니다. 커널 작업 종료를 보장하는 값은 아닙니다. 끝나지 않은 작업을 중복 실행하지 않고 개수를 제한합니다. GPU 순서는 실행 중 유지되며 확장을 다시 시작하면 현재 발견 순서로 새로 구성합니다.
